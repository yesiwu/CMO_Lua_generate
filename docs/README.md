# docs

## 1. 目录定位

`docs` 保存长期维护的架构、契约和实施计划，不替代代码注释或运行日志。

## 2. 核心职责

解释目录边界、调用关系、输入输出契约、外部 CMOLua 版本和阶段性决策。

## 3. 输入与输出

输入是已确认的代码行为和设计决策；输出是 Markdown 文档和可审阅的变更记录。

## 4. 主要文件

`architecture/` 放结构；`contracts/` 放 JSON/Manifest；`plans/` 放实施计划。

## 5. 依赖关系

文档引用代码，但生产代码不得运行时依赖 docs。

## 6. 禁止职责

不得把未验证的建议写成已实现行为，也不得存放秘密和完整运行日志。

## 7. 典型调用链

代码变更 -> 更新契约/架构说明 -> 测试 -> 发布记录。

## 8. 测试要求

路径和示例命令应可验证；版本清单需能追溯到文件 hash。

## 9. 当前开发状态

部分实现，目录索引正在建立。
