# CMO Lua Capability Renderer 重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务实施。所有步骤使用复选框跟踪；严格执行 TDD、阶段验收和小步提交。

**Goal:** 将当前面向固定海空反舰场景的 JSON→Lua 生成链重构为“确定性 Capability Renderer + 受控 LLM 能力实验室”，统一普通 JSON、Baseline、Candidate 和 Campaign 的 Lua 生成入口，同时保留旧链作为可回退兼容后端。

**Architecture:** 原始输入先经过既有校验、IR 和数据库解析，形成 `ScenarioDefinition + ScenarioSetupSpec + StrategySpec + ExecutionPolicySpec`。两个 Compiler 将它们降低为类型化 Operation，`CapabilityResolutionService` 只解析已经注册的 Capability，`UnifiedLuaRenderer` 确定性生成 Lua、Source Map、Generation Manifest 和 Telemetry Contract。LLM 仅用于异构 JSON 映射、结构化 StrategySpec 生成，以及隔离的 Primitive Lab；正式 Candidate/Campaign 不允许自由生成 Lua。

**Tech Stack:** Python 3.11+、dataclasses/Pydantic 风格领域模型（遵循仓库既有模型方式）、pytest、SQLite 只读 CMO 数据库、现有 CMO BatchRunner、现有 Agent/Tool/Hook/ArtifactStore、Lua、SHA-256 内容校验。

## Global Constraints

1. 现有 V1 JSON 输入必须继续可用，迁移期不得要求用户批量重写历史 JSON。
2. `CMOLua-main/tools/json_to_lua.py` 冻结为 `LegacyManifestGenerationBackend`，迁移期不得删除，也不得继续增加新能力。
3. 已注册 Capability 的正式 Lua 必须确定性生成：同一 Canonical 输入、Capability 版本、Runtime 版本和 Renderer 版本得到字节一致输出。
4. LLM 不得编造或修改 DBID、LoadoutID、GUID、官方评分片段、场景事实和数据库解析结果。
5. Renderer 不得根据字符串猜平台类别，不得包含 DBID fallback，不得在 Loadout 失败时创建裸机继续执行。
6. Renderer 不得隐式完成射手—目标配对、弹药均分、航路推导、默认战术时序等策略决策。
7. `OMNI`、`autodetectable`、Doctrine、EMCON、清弹和装弹必须由显式 Setup/Execution Policy 控制，不得由模板偷偷开启。
8. CapabilityGap 在正式运行中必须 fail closed；不得自动调用 LLM 生成 Lua 并继续 Candidate 或 Campaign。
9. Phase 3–9 只消费稳定的正式产物和结构化 Outcome，不得依赖具体 Lua 模板内部结构。
10. Skill 是知识来源，不是运行时真值；只有经过验证的规则和注册 Capability 才能进入正式生成链。
11. 所有新代码采用 TDD；每个任务必须先看到预期失败，再实现最小通过代码。
12. 本重构前半程不运行真实 CMO；真实 CMO 只在明确标注的 Behavior Golden、Shadow Compare 和 Smoke 验收中人工批准后执行。
13. 不对无关模块做大规模整理；所有重构必须服务于统一 Lua 生成链。
14. 每个阶段必须保持主分支测试通过，并提供可回退配置。
15. 不允许一次性删除旧适配器、旧 Workflow 或旧产物格式。

# 1. 为什么已有代码必须继续管理

答案是：**必须管理，但不是全部重写。**

此次重构影响 Lua 生成核心，却不代表前面已完成的文件和 Phase 1–9 都失效。正确方式是把现有资产分为五类：

```text
继续复用
需要扩展
改造成门面/适配层
冻结为 Legacy
待新链稳定后弃用
```

不能采用：

```text
删除旧 JSON 链
→ 重新写完整系统
→ 再把 Phase 3–9 接回来
```

因为这样会同时破坏数据库解析、产物目录、评分、候选评测、经验学习、Skill 晋升和 Campaign。

# 3. 核心领域模型

## 3.1 `ScenarioDefinition`

只描述客观事实：

```python
@dataclass(frozen=True, slots=True)
class ScenarioDefinition:
    scenario_id: str
    name: str
    sides: tuple["SideDefinition", ...]
    units: tuple["UnitDefinition", ...]
    database_version: str
    source_checksum: str
```

`UnitDefinition` 至少包含：

```python
@dataclass(frozen=True, slots=True)
class UnitDefinition:
    stable_id: str
    declared_name: str
    side_id: str
    platform_category: Literal[
        "aircraft", "ship", "submarine", "facility", "satellite"
    ]
    dbid: int
    loadout_id: int | None
    initial_position: "PositionSpec | InheritBasePosition"
    base_unit_id: str | None
    declared_inventory: tuple["WeaponInventory", ...]
```

不得包含：

- 谁攻击谁；
- OMNI；
- autodetectable；
- 清弹策略；
- 自动航路；
- Event 事件实现。

## 3.2 `ScenarioSetupSpec`

描述环境设置，不描述战术：

```python
@dataclass(frozen=True, slots=True)
class ScenarioSetupSpec:
    side_postures: tuple["SidePostureSpec", ...]
    awareness_policy: Literal[
        "scenario_declared",
        "organic_detection",
        "fixture_full_awareness",
    ]
    emcon_policy: Literal["scenario_declared", "explicit"]
    target_visibility_policy: Literal[
        "scenario_native",
        "force_autodetectable_fixture",
    ]
    doctrine_policy: Literal[
        "scenario_declared",
        "explicit",
        "free_fire_fixture",
    ]
    inventory_policy: Literal[
        "preserve_existing",
        "validate_only",
        "reset_to_declared",
    ]
    unit_creation_policy: Literal["fail_closed"]
```

## 3.3 `StrategySpec`

描述作战方案：

```python
@dataclass(frozen=True, slots=True)
class StrategySpec:
    strategy_id: str
    parent_strategy_id: str | None
    directives: tuple["StrategyDirective", ...]
    assumptions: tuple[str, ...]
    source: Literal["input", "baseline", "llm_proposal", "manual"]
```

第一批 Directive：

```text
SurfaceStrikeDirective
AircraftStrikeDirective
PatrolDirective（后续）
SubmarineDeployDirective（后续）
```

`SurfaceStrikeDirective` 必须显式包含：

```python
@dataclass(frozen=True, slots=True)
class SurfaceStrikeDirective:
    directive_id: str
    attacker_unit_id: str
    target_unit_id: str
    weapon_dbid: int
    fire_quantity: int
    start_delay_seconds: int
    interval_seconds: float
    intent: str
```

不得把多射手、多目标的模糊列表直接传给 Renderer。

## 3.4 `ExecutionPolicySpec`

描述如何可靠执行既定策略：

```python
@dataclass(frozen=True, slots=True)
class ExecutionPolicySpec:
    contact_resolution: "ContactResolutionPolicy"
    salvo_scheduling: "SalvoSchedulingPolicy"
    runtime_identity: Literal["guid_preferred"]
    event_idempotency: Literal["operation_keyed"]
    error_policy: Literal["fail_closed"]
    max_scheduled_events: int
```

示例：

```json
{
  "contact_resolution": {
    "mode": "wait_for_contact",
    "timeout_seconds": 60,
    "retry_interval_seconds": 5,
    "allow_bol_fallback": false
  },
  "salvo_scheduling": {
    "mode": "staggered_per_round",
    "interval_seconds": 1
  },
  "runtime_identity": "guid_preferred",
  "event_idempotency": "operation_keyed",
  "error_policy": "fail_closed",
  "max_scheduled_events": 64
}
```

## 3.5 `CanonicalExecutionManifest`

这是新的单一数据源，不是 `manifest.lua`：

```python
@dataclass(frozen=True, slots=True)
class CanonicalExecutionManifest:
    scenario: ScenarioDefinition
    setup: ScenarioSetupSpec
    strategy: StrategySpec
    execution_policy: ExecutionPolicySpec
    resolved_database_facts: "ResolvedDatabaseFacts"
    contract_version: str
    checksum: str
```

## 3.6 `Operation`

所有 Operation 共有字段：

```python
@dataclass(frozen=True, slots=True)
class Operation:
    operation_id: str
    depends_on: tuple[str, ...]
    capability_id: str
    source_ref: "SourceRef"
    failure_policy: Literal["fail_generation", "fail_candidate"]
```

第一批 Setup Operation：

```text
EnsureSide
SetSidePosture
SetAwarenessPolicy
ApplyDoctrine
ApplyEmcon
EnsureSurfaceUnit
EnsureAircraft
EnsureSubmarine
EnsureFacility
SetTargetVisibility
ValidateInventory
ResetInventory
ReloadSurfaceWeapon
ApplyAircraftLoadout
```

第一批 Runtime Operation：

```text
ResolveRuntimeUnit
PersistUnitHandle
ResolveTargetContact
WaitForContact
PersistRuntimeState
ScheduleEventAction
VerifyEventRegistered
CleanupEventArtifacts
EmitTelemetry
```

第一批舰船打舰船 Operation：

```text
PrepareSurfaceAttack
ScheduleSurfaceSalvo
SubmitContactAttack
VerifyWeaponExpenditure
```

## 3.7 `CapabilityDefinition`

```python
@dataclass(frozen=True, slots=True)
class CapabilityDefinition:
    capability_id: str
    version: str
    operation_type: str
    parameter_schema_checksum: str
    supported_platform_categories: tuple[str, ...]
    renderer_binding: str
    required_runtime_helpers: tuple[str, ...]
    allowed_cmo_apis: tuple[str, ...]
    forbidden_cmo_apis: tuple[str, ...]
    telemetry_contract_id: str
    liveness_contract_id: str
    verified_database_version: str
    verified_runtime_version: str
    status: Literal[
        "registered", "deprecated", "disabled"
    ]
    checksum: str
```

## 3.8 `CapabilityGap`

```python
@dataclass(frozen=True, slots=True)
class CapabilityGap:
    operation_id: str
    capability_id: str
    reason: Literal[
        "unregistered",
        "version_incompatible",
        "platform_unsupported",
        "runtime_incompatible",
    ]
    required_platform_category: str | None
```

出现 `CapabilityGap` 时正式生成失败，不允许 LLM兜底。

# 25. 计划结论

此次重构不是“把旧文件全部推翻”，而是：

```text
保留成熟校验、数据库、产物、执行、评分和 Campaign
冻结旧 json_to_lua.py 为 Legacy
抽离隐式策略和 Fixture 设置
建立 Canonical 四层模型
统一降低为 Typed Operations
通过 Capability Registry 确定性渲染
用 Telemetry/Liveness 证明实际执行
用隔离 Primitive Lab 扩展新能力
```

LLM 的正式位置只有：

```text
未知 JSON → Mapping Proposal
场景与目标 → StrategySpec
CapabilityGap → 离线 Primitive Design/Implementation Proposal
```

LLM 永远不应该处在：

```text
正式 Candidate/Campaign
→ 自由生成完整 Lua
→ 直接执行
```

该计划完成后，现有系统不会失去 Phase 1–9 的成果，而是把 JSON 入口和 Candidate 入口收敛到同一套可验证、可扩展、可回滚的 Capability Renderer。
